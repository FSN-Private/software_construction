# Local failed-cycle publication proposal

Status: owner explicitly approved this scoped local implementation and tests on 2026-10-08. The verifier now retains and retries signed failure envelopes locally; no live AWS delivery has occurred.

The existing `RecoveryCycleEventV1` and `RecoveryCycleEnvelopeV1` contracts in `packages/recovery/RecoveryCatalogContracts.cs` define the exact message. The payload contains schema version, event ID, optional capture/point IDs, owner/library IDs, UTC observation time, stage, optional failed data class, outcome, safe code and recovery-worker build digest. Its envelope contains schema version, `recovery_cycle` message type, worker/signing-key identifiers, public-key fingerprint, payload digest, canonical payload and signature.

The proposed verifier path permits stages `verification` or `publication`, outcomes `incomplete` or `failed`, and failed class `recovery_records`. Safe codes must come from a fixed application allowlist; arbitrary exception text cannot become a code. It excludes media, paths, object locators, credentials and raw errors.

The local implementation signs with the existing evidence key, persists exact signed bytes at `POINT#<event-id>/CYCLE` in the separate VerificationTable, and retries those bytes through only the configured primary recovery-observation queue whose URL and ARN match the configured account, region and name. Event identities distinguish consecutive failures at the same recovery point. The owner separately approved the verifier-role/table definition. No new IAM permissions, AWS deployment, actual message delivery or deletion is authorized by this contract.

Required local tests cover the fixed field allowlist, safe-code rejection, exact queue binding, signed-byte retries, interrupted delivery, and absence of sensitive error/path fields. Failure publication must never create a healthy catalog or override independent purge authority.

The envelope and configured `OWNER#<scope>/CYCLE_PENDING` pointer are written atomically using the approved point PutItem and owner UpdateItem permissions and existing allowed attributes. The pointer contains only owner/library, event ID and envelope digest; it never alters `OWNER/VERIFIED`, audit authority, copy records or fences. Each invocation drains that exact signed outbox before latest-point discovery, so a newer point cannot strand an older failed send. Delivery is marked conditionally before clearing the matching pointer; unknown outcomes replay without replacing timestamps/signatures. Pre-discovery failures retain null recovery-point/capture identities. Recovery tests exercise accepted-but-lost send, committed-but-lost transaction/delivery responses, delivered replay, consecutive events at one point, invalid codes and foreign queue rejection. Local checks do not establish live alert delivery.
