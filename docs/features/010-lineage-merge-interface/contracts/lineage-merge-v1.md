# Lineage and Merge Interface Contract v1

All routes below `/v1/libraries/{library}/lineage` require the authenticated library owner, return `Cache-Control: private, no-store`, and use safe `code` plus `operationId` errors. Mutations require `Idempotency-Key` and exact expected identities. The existing feature 006 endpoints remain the authority for commit/ref/rewrite/visibility/checkout/recovery operations.

| Operation | Required response and behavior |
|---|---|
| `GET /capabilities` | Owner-scoped `mutationsEnabled` state for disabling web history controls during an incident. Read, prepare, and review remain available. |
| `GET /images/{asset}/history?branch=&offset=&limit=&showHidden=` | At most 100 exact image-changing commits per page, canonical parent IDs, ref/tag labels, current selection, collapsed hidden-ancestry IDs in `hiddenParentIds`, and next-page context. An indexed asset-entry lookup joins derived branch reachability without traversing the whole branch ancestry to select the page. A connector walk from selected nodes stops at the next image-changing commit on each parent path and preserves hidden markers across omitted library-wide commits and merges. Exact parent IDs and the separate branch-head label identify library-wide commits omitted from this image filter. |
| `GET /images/{asset}/compare?target=&source=` | Exact target/source/base commit and XMP identities, each side's image state, XMP/path/lifecycle differences, verified recognized-field and opaque differences, and two independent existing preview/provenance states. `not_requested` means the browser may request the exact version through feature 008. No-current-preview fallback. Missing authoritative content keeps digest differences visible and marks fields unavailable. |
| `POST /merges/prepare` | Source/target ref and head, base or explicit absence, policy version, complete affected asset/edit list plus unchanged target identities, proposed XMP identities, conflicts, preview states and provenance, and a canonical proposal digest. The digest covers immutable proposal inputs and excludes live preview status. No mutation. |
| `POST /merges/review` | Re-evaluate the proposal with every explicit conflict choice. Return complete resolved identities, exact XMP bytes in base64, paths/lifecycle, retained states, and a review digest. No mutation. |
| `POST /merges/confirm` | Reviewed proposal and result digests, exact expected heads, complete conflict choices, and confirmation. Re-evaluate both heads and content, then pass prepared resolver entries to feature 006 publication. Its transaction checks both refs and returns immutable commit/operation ID or no commit. |

`stale_head`, `stale_working_state`, `unresolved_divergence`, `protected_ref`, `dirty_checkout`, `content_not_authoritative`, `preview_unavailable`, and `recovery_expired` never include private XMP, location, path, or commit-message content. Confirm replays with the same idempotency key and payload return the original result; a changed payload under the same key is rejected. The owner must refresh and review a changed proposal before a new confirmation.

## XMP merge policy `xmp-merge-v1`

The policy reads at most the gallery's XMP byte limit with DTD and external entity resolution disabled. It recognizes rating, rejected, color, tags, title, description, and location. It compares each field against the common base. Only changes to distinct recognized fields can compose automatically. Simultaneous changes to one field, cross-side rating/rejection changes, and any change outside those fields require a selected target or source value. Processing history and masks are outside the recognized fields. A missing base, malformed XML, multiple RDF descriptions, or duplicate field representations cannot compose. The generated result is deterministic XML; the owner reviews its exact digest before confirmation. Unknown content uses one exact owner-selected side as its starting point, then selected recognized values are applied to it.

Server-generated combined XMP carries owner/library/asset/edit and exact base/target/source digest provenance. The generated result is accepted by feature 006 only after object verification; the browser cannot submit arbitrary XMP through this contract.

The web's branch, tag, commit, hide/reveal, restore/revert, recovery, rewrite, and checkout controls delegate to feature 006's [version-control contract](../../006-xmp-version-control-core/contracts/version-control-v1.md). The gallery entry retains its URL query and displays uncommitted web changes separately from committed history.

Accepted tag creation and removal link their exact reflog entry to an audit event by `vc_reflog.audit_event_id`. An owner-scoped join provides the operation ID, actor, normalized tag name, affected old/new commit, event type, and accepted outcome without emitting the private tag name to operational logs.
