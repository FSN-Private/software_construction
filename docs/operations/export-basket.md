# Export basket operations

Feature 012 capability defaults to disabled (`Exports:Enabled=false`). Schema 021 is additive and is included in the migration artifact; basket/source identities and prior readers remain intact. Baskets never acquire or release original/XMP/history holds. Approval of the design does not enable deployment.

Owner-scoped baskets support 20 saved baskets, 250 pinned selections, revisions, a default basket and explicit duplicates. Selection resolves current/main, branch/tag or exact committed history once; mutable working selections are rejected. Hidden selection requires explicit advanced history. Missing bytes are unavailable, never proof of permanent purge.

Basket readiness and output names follow the selected originals/rendered preset. Missing or unavailable XMP can prevent rendering without preventing an eligible unchanged-original export; the original extension is retained in its safe output name. Rendered-preview readiness remains separate and does not become available merely by choosing originals.

Feature 011 integration uses the trusted in-process durable tombstone consumer described in feature 012 contracts/purge-invalidation.md. There is no public tombstone publisher. Original versus XMP and logical asset/edit scope preserve other retained deduplicated images and original-only exports. Do not acknowledge export cleanup while admitted or unknown writes remain; lease expiry is not proof of writer quiescence. T029 gates complete acceptance and production enablement on real feature 011 purge evidence.

Preparation/download/cleanup/operator controls are implemented locally; acceptance and production enablement remain gated by the evidence listed below.

Request discovery includes all retained work and the newest 200 expired/cancelled/unavailable records; older terminal evidence remains accessible through owner/library-scoped request-ID pagination. The browser preserves loaded history and announces meaningful polled state/outcome/download-readiness changes without moving focus. Revocation creates a durable session record even before the first download grant, and bearer diagnostic streams also register/check that record. Expired-JWT logout clears local private drafts and proceeds to Cognito logout; it does not report successful server revocation. Live/unknown-expiry revocation failures remain visible and retryable.

## Implemented controls and limits

Owner submissions create immutable requests and fingerprints; presets include unchanged originals and JPEG 2048 private/retained renderer metadata. Originals and retained metadata require explicit disclosure consent; 100 selections or 1 GiB estimated source bytes require cost acknowledgment. Configured defaults: 250 items, 20 baskets, 10 retained requests, 10 GiB ZIP, 7200-second preparation and 24-hour retention. Lower item/package/duration limits are available; retention currently remains exactly 24 hours.

Packages use bounded streaming and unique write-intent destinations. Workspace capacity reserves 50 GiB in the API task. Native download bootstrap codes last at most 60 seconds; cookies last at most five minutes and never outlive the bearer that minted them. Session identity uses Cognito origin_jti/auth_time so token refresh does not bypass sign-out revocation. Range requests recheck current completed-pin eligibility and request state; progressing transfers periodically recheck revocation/lifecycle. Downloads never use Gateway response bodies or public S3 links.

Credential expiry authorizes transfer admission: every new GET/HEAD/range request requires valid credentials, including a fresh exchange after a cookie expires. A transfer admitted while credentials were valid may finish after credential expiry. Its progressing-stream checks still enforce explicit session revocation, package expiry, cancellation and lifecycle invalidation; expiry of credentials alone does not interrupt it.

Operator group plus configured Exports:OperationsUsername authorizes aggregate GET /v1/exports/operations and POST /{pause,resume,drain,cancel-pending}; these routes expose no owner media or selection details. Pause stops intake and claiming; existing preparation continues. Drain prevents new intake/claiming and allows admitted work to finish. Cancellation fences publication and revokes grants. Separate maintenance continues while preparation runs and while the capability is disabled, expires packages, recovers expired leases and cleans settled terminal-intent versions. Unknown writes remain draining.

Aggregate inspection includes pending/active/cleanup/unknown/failed counts, item outcomes, basket items, oldest queued age, expiry and cancellation totals. The hosted ExportMetricLoggingService collects only ten explicitly allowed Platform.Api export instruments into existing JSON logs with EventType=exports.metric, MetricName and finite nonnegative MetricValue; it discards every tag. CloudWatch filters in Platform/Exports collect basket size, queue age, preparation duration/failures, observed render failures, item outcomes, package bytes, download attempts and policy denials. The operations dashboard graphs these measurements; counters use Sum and sampled sizes/durations use Average (other statistics can be selected in CloudWatch). Item status counts, expiry and cancellation totals remain available through the aggregate endpoint. Expiry, cancellation, per-item publication, denied access and operator actions retain durable audit evidence. Sustained worker/provider/cleanup failures feed the export alarm over three five-minute periods. Use the aggregate endpoint and safe reason codes during diagnosis; do not copy snapshots, source paths, tokens or media into logs.

The private derivative bucket has a separate exports/ lifecycle backstop: current and noncurrent versions expire after three days and incomplete multipart uploads abort after three days. This preserves the 24-hour availability interval measured from publication even when preparation takes the configured maximum two hours. Application cleanup still enforces cancellation/expiry/purge promptly; lifecycle timing is asynchronous and is never evidence for purge acknowledgment, writer quiescence or source deletion. The derivatives/ cache rule remains independently scoped.

Preparation duration measures elapsed time from immutable-request acceptance to a terminal outcome, including queue/render waiting; pending retries do not produce separate duration samples. Prepared counts completed/partial packages; failure counts include partial packages with failed items and terminal failures. Superseded/cancelled generations do not emit preparation-failure alerts. Collected renderer/terminal-failure events and worker/cleanup failures feed the same sustained alarm; duplicate observations within a period do not change its threshold-one, three-period behavior.

## Failure handling and recovery limits

Provider outage: pause intake, inspect aggregate backlog and safe reason codes, restore the approved renderer/storage dependencies, then resume. Renderer retries are bounded to three attempts and the request-wide duration. Integrity failures never publish unverified bytes; review the immutable reason/manifest, repair authority through its owning subsystem, and submit a new snapshot. Quota exhaustion requires removing basket selections or waiting for retained requests to expire; failed requests expire after 24 hours. Do not change immutable requests to substitute current versions.

Unknown or abandoned writes: **do not** set knownOutcome=true or state=cleaned merely because a lease expired, a timeout elapsed, a prefix is temporarily empty, or a process disappeared. Each serial multipart call records admission before storage and its successful response afterward; the export-specific SDK client disables automatic retries. Successful completion records its provider receipt/version and permanently closes that intent's writer admission. Cleanup can recover a lost settlement callback from that positive terminal evidence. Initiation/part receipts and ambiguous issued calls remain draining; an empty listing or an abort request does not settle them. Preserve the journal and investigate the provider operation; there is no owner/operator force-settlement control.

Local input/ZIP workspaces have durable inventories before media writes. Normal exit declares writer quiescence and verifies removal. Recovery removes an inventoried workspace only on the same host after explicit writer shutdown or OS proof that its exact process identity has ended (including PID reuse detection); the path must match its generated child under the configured workspace root. Foreign/unavailable volumes remain draining until positive volume-destruction evidence is integrated. Do not treat process/task disappearance as proof of S3 settlement. T030 local paused-write, process-death, callback-loss, unknown-initiation and inspection/deletion-failure checks pass; T014 deployment recovery evidence remains open.

Authorization incident: pause intake, revoke the originating download session, cancel affected in-progress requests and disable exchange/download capability. Retain safe audit and tombstones. Cancellation backlog: inspect unknown writes separately from settled deletion failures; resolve proven operations and retry version/multipart cleanup, preserving shared renderer derivatives. Retention conflict: trust only the feature 011 transactional tombstone publisher, not storage 404s or operator inference.

## Transport rollout and rollback prerequisites

`exportTransport=true` opt-in CDK context provisions an internal ALB and CloudFront VPC origin; bootstrap default creates neither. Supply ExportCloudFrontPrefixListId with the regional AWS-managed com.amazonaws.global.cloudfront.origin-facing prefix-list ID. The private listener admits only download/session paths with a secret origin header. Viewer HTTPS, no caches/error caches/logging/compression and range/cookie forwarding are required. Regional prefix-list and VPC-origin prerequisites follow https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-vpc-origins.html. The ALB adds fixed cost even with ECS at zero; explicitly budget and remove the opt-in transport through an authorized infrastructure update when sleeping nonproduction. Do not assume the existing ECS/RDS sleep script removes it.

Deploy additive schema first, leave API Exports:Enabled and web exportsEnabled false, validate controls/transport and complete T029 before production enablement. Rollback disables new submission/exchange, revokes sessions, cancels/drains work and keeps maintenance/schema/audit/tombstones until cleanup is proven. Never roll back by deleting evidence or exposing unsigned storage.
