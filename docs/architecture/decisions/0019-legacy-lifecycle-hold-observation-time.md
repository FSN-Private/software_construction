# ADR-0019: Bind legacy lifecycle holds to trusted observation time

**Status**: Accepted by explicit owner approval on 2026-10-13 for local implementation/tests
**Decision owner**: Product owner
**Related**: [Feature 011](../../features/011-backup-disaster-recovery/spec.md), T035; supplements [ADR-0018](0018-recovery-purge-custody-and-snapshot-preservation.md)

Migration 005 did not record lifecycle-hold creation time. Use the earliest authenticated snapshot containing the exact legacy hold definition as its conservative creation identity for independent release. This is an observation timestamp, not a claim about the actual historical creation date. New holds record creation UTC through an additive nullable column and insert default; existing rows remain null, without invented backfill.

Require complete strongly read owner-point history, exact signed checkpoints/dumps, unchanged hold definitions and selection of the earliest matching point. A bounded private history-bindings file names all distinct owner points and their independently verified historical release expectations; existing `GetItem` membership/count checks establish completeness without adding Query/Scan authority. Every historical expectation must match its signed owner-access proof and exact captured release/configuration evidence. The selected old snapshot uses its own hash-pinned migration directory, while the new proof records the actual executing worker's digest. No credential/account/owner/trust override is accepted. Primary row deletion or a caller-supplied earlier timestamp cannot replace this evidence. Nullable creation columns are omitted from legacy definition hashing so pre-migration and post-migration observations retain the same identity. A real non-null creation timestamp is part of a new hold's definition. Changed or reused identities fail closed.

The signed owner approval and recovery proof bind the resolved timestamp, exact definition and checkpoint. All 90-day obligations still start at the independently observed release UTC; choosing an earlier creation identity never shortens them. Retention history rederives the timestamp before accepting a lifecycle release. Foreign asset ownership, incomplete/changing history or unsupported historical evidence prevents release.

The alternative was leaving legacy indefinite holds protected pending a separate migration; that avoids resolving provenance now but continues blocking eligible purge. The approved option permits release from independently retained evidence while preserving protection. Whole-history inspection can be costly; no new IAM or evidence namespace is introduced. Rollback disables lifecycle release and retains holds/proofs/copies. No live migration, deployment or deletion is authorized. Full workflow qualification remains T035/T024/T026.
